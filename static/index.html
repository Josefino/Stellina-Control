Sensor temperature (estimate: ambient + °C)—

The ambient temperature/humidity in sensors is the telescope's current reading (it matches dewpointDepression, which the firmware uses for defogging); the sensor estimate is always computed from it. The one exception: the firmware takes a fresh ambient sample at the start of every capture and stores it in the running capture (startTemperature/startHumidity). That value is shown as Fresh reading above whenever an observation or dark-frame capture is running — so to get an up-to-date number without restarting, start any short capture and watch that line. Refresh now re-pulls app/status (picks up the fresh reading while a capture runs). The camera sensor temperature is not in the live status at all — only in each frame's FITS TEMP header — so it is estimated here as ambient + your measured offset (default 6 °C).

Telescope service discovery

OpenStellina identifies ports 8082 and 8083. First test TCP connectivity only. FTP is not used for these tests.

A TCP port being reachable does not establish that telescope control is available.

Socket.IO handshake (optional)

OpenStellina uses Engine.IO v3 polling at /socket.io/ on port 8083. This sends a single HTTP GET and reads the initial handshake. It does not request control, move motors, or initialize the telescope.

The server may temporarily allocate a Socket.IO session. Run only once when needed, not repeatedly.

Passive WebSocket session

Connect to Engine.IO v3 / Socket.IO on port 8083 for up to 12 seconds. Capture incoming frames and protocol handshake. Respond only to required heartbeat messages. No control request, Socket.IO application events, or motor commands are sent.

Only one diagnostic connection at a time. The connection is explicitly closed after the test.

Dark library (calibration) — usually not available on Stellina

The telescope can keep its own dark/bias calibration library (darkManager/generateDark → /system/dark, /system/bias) and subtract it while stacking. But it needs a magnetically-detected lens cap (the Filter status must read DUST) — that detectable-accessory system is a Vespera-family feature. The original Stellina has no such cap, so the firmware refuses with DUST_FILTER_MISSING and the official Singularity app hides "make dark" on Stellina too. Kept here for Vaonis models that support it. On Stellina, use the expert-mode darks above instead (cover the aperture, match exposure/gain, subtract in processing). Needs Take Control; runs ~30 min in 3 steps.

Night plan (Sequencer)

The telescope runs the whole plan itself — it auto-initializes and moves target to target on schedule, and keeps going even if you disconnect the Mac or Raspberry Pi. Requires Take Control and an idle telescope. No prior Auto-Init needed; the plan does its own.

×

Click a result to add it with the minutes, rotation and field of view above. Rotation blank = the object's catalog orientation. Field of view: single frame 1.1° × 0.7° or mosaic. In a plan, Stellina builds one fixed mosaic size, 1.6° × 1.1° (other models: custom size). Deep-sky only, not with Full resolution; rotation turns it. A custom mosaic for a direct observation is set in Manual target on the Observation tab. Sub-exposure and gain prefill from the catalog. Every value can be edited per target in the list below. Targets run back-to-back in this order.

Framing preview (offline chart / Aladin)

Park / shut down at the end is done by this app: keep it running and connected until the plan finishes. It parks right away (parking does not disturb saving) and before power-off waits until the telescope has finished saving the final TIFF (storage unchanged for 30 s). A plan you stop yourself never triggers it.

HTTP Authorization (local)

The Authorization header is computed locally on this Mac from the live challenge (Ed25519 signature, algorithm from pyvaonis). No internet and no external server are used. A fresh header is computed for every request because the challenge rotates with each status push.

Set system time sends the Mac clock over the Live WebSocket (as the official app does on connect). Verify (requires Take Control, refused while an operation runs) sends POST :8082/v1/general/stopAutoInit three times: no header, wrong signature, correct header. With no initialization running it does nothing.
